# Stripe セキュリティチェックリスト（#84）を Claude in Chrome にやらせるプロンプト

ブラウザ操作エージェント（Claude in Chrome）に下書き・入力させるためのプロンプト。**送信は人が確認してから押す**設計にしてある。

## プロンプト（ここから下をまるごと Claude in Chrome に貼る）

## 絶対に守ること

1. 「送信」「Submit」「Provide information」などの最終確定ボタンは、私の確認を取ってから押す。押す前に入力内容の一覧を見せ、私が「送信して」と言うまで待つ。
2. API キーの画面（シークレットキー sk_live_ / sk_test_、Webhook の署名シークレット whsec_）は開かない。値を表示・コピー・要約・引用しない。画面に出てしまったら、その部分には触れず「キーが表示されています」とだけ報告する。
3. チェックリスト以外の設定は変更しない。商品・価格・Webhook・支払い方法・銀行口座・チームメンバーは読むだけ。
4. 事実が分からない設問は推測で埋めない。「この設問は回答できません」として私に聞く。
5. 多要素認証（MFA / 2 段階認証）が有効かを問う設問は、私が「有効にした」と言っていない限り「はい」にしない。

## 手順

1. https://dashboard.stripe.com/settings/business を開き、「アカウントのステータス」または赤帯の「A required task is past due」から該当タスクの「Provide information」を開く。見つからなければ https://dashboard.stripe.com/settings/update も見る。画面が本番モードであることを確認する（サンドボックスではない）。
2. 設問をすべて読み取る。ページをまたぐ場合は最後まで進んで全部集める。読み取った設問を日本語で一覧にして私に見せる。選択式なら選択肢も書く。
3. 下の「サービスの実態」だけを根拠に各設問の回答案を作り、設問と並べて私に見せる。自由記述は日本語で書く（画面が英語のみを受け付けるなら英語でもよい。あなたが判断してよい）。
4. 私が OK を出した設問だけ入力する。入力し終わったら確定ボタンの直前で止まり、もう一度全体を見せる。
5. 送信後、進捗表示（送信済み → 審査中 → 完了）のどこにいるか、審査期間の記載があれば日数を報告する。

### 「Billing の概要」（`/billing/setup`）は使わない（2026-09-17 1:36、利用者が共有）

利用者が Stripe の **請求する → Billing の概要**（「収益管理、ワークフロー自動化、決済受け付け」「始める」ボタン）を開いた。

**この画面は不要。「始める」は押さなくてよい。**Billing の使い方を案内するページで、ここで設定しないと使えないものは無い。
このサービスは**自前のコードから Stripe Checkout を呼ぶ**方式なので、Stripe 側で要るのは次の 4 つだけ:

1. 商品と価格（商品カタログ）
2. Webhook エンドポイント
3. カスタマーポータルの設定
4. シークレットキー（`sk_live_`）

トライアル（初月無料 30 日）と割引コードの受け付けは**コード側で指定済み**なので、Stripe の画面での設定は要らない
（`src/lib/billing/trial.ts` の `DEFAULT_TRIAL_DAYS = 30`、`src/lib/billing/stripe.ts` の `trial_period_days` と `allow_promotion_codes: true`）。
`STRIPE_TRIAL_DAYS` を設定すれば日数を変えられる。

### 審査を待たずに今できること（#58 の ⑧ の前半）

**商品・Webhook・ポータル・キーの作成は、決済が停止中でもできる。**審査待ちなのは「実際に課金が通るか」だけ。
つまり ⑧ のうち**最後の本番テスト決済だけ**が審査結果に依存する。お客様に `/plans` の「申し込む」を使わせるのは、その確認が取れてから。
