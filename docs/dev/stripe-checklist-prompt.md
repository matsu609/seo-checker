# Stripe セキュリティチェックリスト（#84）を Claude in Chrome にやらせるプロンプト

2026-09-09 付で期日超過している「Additional information required（日本の加盟店に必須のセキュリティチェックリスト）」への回答を、
ブラウザ操作エージェント（Claude in Chrome）に下書き・入力させるためのプロンプト。**送信は人が確認してから押す**設計にしてある。

## 渡す前の準備

| # | サービス・画面 | URL | やること |
|---|---|---|---|
| 1 | Stripe → ログイン | https://dashboard.stripe.com/login | ログイン済みの状態にしておく（エージェントにパスワードを触らせない） |
| 2 | Stripe → プロフィール → 二段階認証 | https://dashboard.stripe.com/settings/user | **先に 2 段階認証を有効にする**（#84 の設問で問われる可能性が高い。有効にしないと「いいえ」と答えることになる） |
| 3 | Vercel → アカウント設定 | https://vercel.com/account/authentication | 同じく 2 段階認証。本番サイトと Stripe の秘密鍵を持つアカウントのため |
| 4 | Clerk → ユーザー設定 | https://dashboard.clerk.com/user/security | 同じく 2 段階認証 |
| 5 | Stripe → 本番モードに切替 | https://dashboard.stripe.com/ | 画面左上が「テスト環境 / サンドボックス」ではなく**本番**になっていることを確認（チェックリストは本番アカウントのタスク） |

2〜4 を先に済ませておくと、チェックリストで MFA を問われたときに正直に「はい」と答えられる。
間に合わないときは「設定作業中」と答えさせる（プロンプトにそう書いてある）。

## プロンプト（ここから下をまるごと Claude in Chrome に貼る）

```
あなたはブラウザ操作アシスタントです。Stripe ダッシュボードで「セキュリティチェックリスト（Additional information required）」への回答を進めてください。私は Stripe に既にログインしています。

## 絶対に守ること

1. 「送信」「Submit」「Provide information」などの最終確定ボタンは、私の確認を取ってから押す。押す前に入力内容の一覧を見せ、私が「送信して」と言うまで待つ。
2. API キーの画面（シークレットキー sk_live_ / sk_test_、Webhook の署名シークレット whsec_）は開かない。値を表示・コピー・要約・引用しない。画面に出てしまったら、その部分には触れず「キーが表示されています」とだけ報告する。
3. チェックリスト以外の設定は変更しない。商品・価格・Webhook・支払い方法・銀行口座・チームメンバーは読むだけ。
4. 事実が分からない設問は推測で埋めない。「この設問は回答できません」として私に聞く。
5. 多要素認証（MFA / 2 段階認証）が有効かを問う設問は、私が「有効にした」と言っていない限り「はい」にしない。

## 手順

1. https://dashboard.stripe.com/settings/business を開き、「アカウントのステータス」または赤帯の「A required task is past due」から該当タスクの「Provide information」を開く。見つからなければ https://dashboard.stripe.com/settings/update も見る。画面が本番モードであることを確認する（サンドボックスではない）。
2. 設問をすべて読み取る。ページをまたぐ場合は最後まで進んで全部集める。読み取った設問を日本語で一覧にして私に見せる。選択式なら選択肢も書く。
3. 下の「サービスの実態」だけを根拠に各設問の回答案を作り、設問と並べて私に見せる。自由記述は日本語で書く（画面が英語のみを受け付けるなら英語でもよい。あなたが判断してよい）。
4. 私が OK を出した設問だけ入力する。入力し終わったら確定ボタンの直前で止まり、もう一度全体を見せる。
5. 送信後、進捗表示（送信済み → 審査中 → 完了）のどこにいるか、審査期間の記載があれば日数を報告する。

- 連絡先 contact@seo-checker.tokyo 。特定商取引法に基づく表記 https://app.seo-checker.tokyo/legal/tokushoho 、利用規約 /terms 、プライバシーポリシー /privacy

【カード情報の取り扱い（ここが本題）】
- カード番号は当社のサーバーを一切通らない。申し込みは Stripe Checkout のホスト画面、カードの変更・解約は Stripe カスタマーポータルのホスト画面。どちらも Stripe 上の画面にリダイレクトする方式。
- 独自の決済フォームは持たない。Stripe Elements も使わず、iframe 埋め込みもしていない。
- カード番号・有効期限・セキュリティコード（CVC）・カード名義は、どこにも保存していない。ログにも出力していない。
- 当社が保持するのは Stripe の顧客 ID（cus_ で始まる ID）、サブスクリプション ID、契約状況・金額・次回更新日だけ。
- PCI DSS の区分では SAQ A に相当する構成（カード情報の入力と保持を完全に Stripe へ委託）。

【システム構成】
- アプリ: Next.js。ホスティングは Vercel。全ページ HTTPS（証明書は Vercel 管理）。
- 認証: Clerk（Google アカウントでのログイン）。パスワードを当社で保持しない。
- データベース: Supabase（PostgreSQL）。保存しているのは診断対象のサイト URL、店舗情報、診断結果、顧客の氏名・メールアドレス相当の情報のみ。決済情報は保存していない。
- 管理画面 /admin は「Clerk でログイン済み かつ 確認済みメールアドレスが環境変数 ADMIN_EMAILS に一致」の 2 条件で制限。管理者は代表 1 名のみ。
- Stripe の Webhook は署名検証つき（署名シークレットで検証し、検証に失敗したリクエストは 400 で拒否）。古いイベントで新しい契約状態を上書きしない実装。
- API キー・シークレットは Vercel の環境変数（Secret）に保存し、ソースコードには含めない。ソースコードの GitHub リポジトリはプライベート。
- 決済データにアクセスできるのは代表 1 名のみ。委託先はすべて SaaS（Stripe / Vercel / Clerk / Supabase / Google Cloud / Anthropic）。

【不正利用・チャージバック対策】
- 不正検知は Stripe Radar の標準ルールに依拠。
- 申し込みにはログインが必須（メールアドレス確認済みのアカウントのみ）。現在は許可リスト運用で、こちらが招待した相手だけが登録できる。
- 解約・カード変更は顧客自身が Stripe カスタマーポータルから実行できる。解約条件（期間末まで利用可、日割り返金なし）は特定商取引法に基づく表記のページに明記している。
- 初月無料のトライアルがあり、その間の課金は発生しない。

【まだできていないこと（聞かれたら正直にこう答える。「はい」と偽らない）】
- 第三者による脆弱性診断・ペネトレーションテストは実施していない。
- 専任のセキュリティ担当者は置いていない。インシデント対応手順書は文書化していない（個人事業のため代表が対応する）。
- ダッシュボードの 2 段階認証について私から何も言われていない場合は「設定作業中」と答える。
```
