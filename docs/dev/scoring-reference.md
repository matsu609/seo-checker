## 0. 全部に共通する約束

数字の出し方について、このサービス全体で守っている決まりです。**個々の採点を読む前にここを読んでください。**

| # | 約束 | なぜ | 実装 |
|---|---|---|---|
| **0** | **打ち手のある項目だけを採点する。**こちら（またはお客様）の作業で動かせない数字は、採点にも KPI にも使わない。文脈として要るものは「参考」として点を付けずに出す | 読んでも動けない数字は、お客様の時間を奪うだけで、報告書の信頼も下げる。コンサルで手を入れられる範囲と評価項目を揃える（利用者の決定 2026-09-19） | 外部からの評価（`src/lib/domain-power/`）は被リンクとインデックス数の 2 つだけ。ドメインの年数・実ユーザーの規模・順位の再掲は 2026-09-19 に採点から外した |
| 1 | **測れなかった項目を 0 点にしない。**分母から外す | キーが未設定なだけのサイトが不当に低く出るのを防ぐ。「弱い」と「測っていない」は違う | 外部からの評価 `status: "unknown"`、MEO `"unavailable"`、クイック診断 `weight: 0` |
| 2 | **分母が 0 のときは 0% ではなく「—」（null）** | 「0% だった」と「計算できなかった」を混同させない | `metrics.ts` の `shareOf` |
| 3 | **率の平均を取らない。**合計 ÷ 合計で出す | 表示 1 回で 1 クリックの行（CTR 100%）が全体を引き上げてしまう | `parse.ts` の `totalsOf`、`ctrOf` |
| 4 | **前期が 0 のときは増減率を出さない。**「新規発生」と書く | 0 で割ると無限大になる。増減率という概念が成立しない | `metrics.ts` の `changeOf` |
| 5 | **「未計測」と「0 件」を書き分ける** | 「ボタンが押されていない」と「押されたことを計測していない」は打ち手がまったく違う | 診断の K01 / K06 / M03、報告書のファネル |
| 6 | **判定の根拠と閾値を必ず画面に出す** | 数字だけ出されても納得できない。改善の根拠にならない | 各報告書の「採点基準」「この数字の出どころ」 |
| 7 | **計算は必ずプログラム。AI に計算させない** | 再現しないうえ検算できない | [diagnosis-rules-spec.md](./diagnosis-rules-spec.md) §2 |
| 8 | **AI は事実シートに無い数字を書けない** | 生成された数値をお客様に渡さないため。本文の数値をシートと照合し、無ければ作り直す | `seo-analysis/ai/verify.ts` |

| グレード | 範囲 | ラベル |
|---|---|---|
| A | 90〜100 | 優良 |

| C | 65〜79 | 改善余地あり |

## 1. クイック診断（サイト・SEO / AIO の採点）

**何を測るか**: 1 ページの HTML が、検索エンジンと生成 AI にとって読み取りやすいか。
**入口**: `/`（ログイン不要・無料）。精密診断の中でもトップページに対して実行します。
**コード**: `src/lib/analyzer/`（`scoring.ts` = 集計、`check.ts` = 判定の型、各ファイルが項目）

### 計算方法

```
カテゴリ得点 = そのカテゴリの獲得点の合計 ÷ 配点の合計 × 100
総合点       = カテゴリ得点をカテゴリ重みで加重平均
```

配点 0 の項目（`info`）は分母に入りません（約束 1）。

### カテゴリの重み（合計 100）

| カテゴリ | 重み | 何を見るか | コード |
|---|---|---|---|
| AI クローラ可否 | 20 | robots.txt が AI 検索用クローラを拒否していないか、noindex、`llms.txt` があるか（有無だけ。2026-09-18 から採点） | `robots.ts` |
| 構造化データ | 25 | JSON-LD の有無と型（Organization / FAQPage / Article など） | `jsonld.ts` |
| メタ情報 | 20 | title / description / canonical / OGP / 言語指定 | `meta.ts` |
| 見出し | 15 | h1 が 1 つあるか、階層が飛んでいないか | `headings.ts` |
| コンテンツ | 20 | 本文量、**本文の具体性**（固有名詞・数字・日付があるか） | `content.ts` |

項目ごとの重みは 1〜3 点です（重要なものほど 3）。

### 注意

- **1 ページだけの採点**です。トップと下層ページで点が変わるのは仕様です。サイト全体を見るときは「サイト診断」を使います。
- 本文の具体性の判定は**多言語対応**しています（r45）。文が少ないページを比率だけで判定しません。
- サイト内検索の結果ページなど、**もともと検索に載せないページ**（noindex か robots.txt で実際に検索から外れているもの）は診断はするが採点せず、サイト全体の平均点からも外します。理由つきで付録に載せます（`analyzer/page-kind.ts` の `searchExclusion`）。

## 2. サイト診断（テクニカル SEO・48 ルール）

**何を測るか**: サイト全体をクロールして、技術的な不備を洗い出す。
**入口**: 精密診断に統合済み（報告書の「詳細: サイト診断」。旧 `/tools/site-audit`）。
**コード**: `src/lib/audit/`（`rules/page.ts` = ページ単位、`rules/cross.ts` = サイト横断、`config.ts` = 閾値）

**48 ルール**を 10 カテゴリ（タイトルタグ / メタタグ / コンテンツ / 見出しタグ / 画像 / カノニカルタグ / 基本的な設定 / セキュリティ / パフォーマンス / 構造）に分けます。
重要度は `error`（重大）/ `warning`（警告）/ `info`（情報）の 3 段です。**自動診断の 4 段（critical / high / medium / low）とは別の型**なので混同しないでください。

### 主な閾値（`src/lib/audit/config.ts`。数値をコードに直接書かない決まり）

| 項目 | 値 |
|---|---|
| title の長さ（全角換算） | 10〜40 文字 |
| meta description の長さ | 50〜120 文字 |
| 本文が薄いと判断する文字数 | 300 文字未満 |
| テキスト / HTML 比が低い | 0.1 未満 |
| 本文の重複と見なす一致率 | 0.8 以上 |
| 入力 URL からのクリック数（深さ） | 4 を超えると深すぎる |
| URL の長さ | 100 文字超 |
| HTML のバイト数 | 1 MB 超 |
| 取得時間（TTFB 相当） | 800ms 超で遅い |
| 取得完了まで | 3,000ms 超で遅い |

クロールの上限は `SITE_MAX_PAGES`（既定 100）、クイック診断だけ `FREE_SITE_MAX_PAGES`（代表 10 ページ）です。

## 3. サイトの構成・信頼（精密診断の差別化部分）

**コード**: `src/lib/seo-analysis/structure.ts` / `trust.ts` / `kinds.ts`

### 構成（数値。点数化はしていない）

被内部リンク数・発リンク数、クリック深度の分布、**内部リンクだけで見た重要度スコア（PageRank 風）**、本文内リンクとナビ・フッターの区別、汎用アンカー（「こちら」「詳しくは」）の割合、行き止まりページ、リンクの偏り、パンくず・OGP・hreflang の有無、更新の鮮度、似た title / h1 の**カニバリ候補**。

### 信頼（9 判定。pass / warn / fail / info）

会社・店舗情報のページ、問い合わせのページ、プライバシーポリシー、特定商取引法に基づく表記、運営者の構造化データ（Organization / LocalBusiness）、電話番号の掲載、住所の掲載、本文と構造化データの **NAP 一致**、記事の著者情報。

**プライバシーポリシーの判定は条件で変わります**: 問い合わせフォームがあるのに無ければ `fail`、無ければ `warn`。特商法は販売していなければ不要なので `info` 止まりです。

## 4. 外部からの評価（旧・ドメインパワー）

**何を測るか**: サイトの外側（よそのサイトからのリンク、Google への登録状況）からの評価のうち、**こちらの施策で動かせるものだけ**。
**コード**: `src/lib/domain-power/`（`score.ts` = 判定、`types.ts` = 定義と打ち手）

> **2026-09-19 に作り直しました。**それまでは無料で取れる 8 指標を配点した 0〜100 の総合点でしたが、
> 100 点のうち 25 点は打ち手が無く（ドメインの年数・実ユーザーの規模）、25 点は施策の結果の再掲（対策キーワードの順位・ブランド名検索の順位）で、
> **いちばん動けない数字がいちばん目立つ**状態でした。約束 0 に従って 2 指標に絞り、**総合点とグレードは廃止**しました。

### 出す指標（点数は付けない）

| 指標 | 出どころ | 判定 | 打ち手（画面に必ず出す） |
|---|---|---|---|
| 外部からのリンクの評価 | Ahrefs の DR（無ければ Open PageRank） | DR 30 以上 = 強い / 10 以上 = 標準的 / それ未満 = これから | 掲載先を増やす（サイテーション調査で未掲載の媒体を洗い出す。業界団体・地域ポータル・取引先・プレスリリース） |
| Google に登録されているページ数 | `site:` 検索の概算件数（SerpApi） | クロールで見つけたページ数の 9 割以上 = 強い / 6 割以上 = 標準的 / それ未満 = これから | 載っていないページを見つけて直す（サイトマップ送信・内部リンク・重複の整理）。中身のあるページを増やす |

**中小企業のサイトでは DR 0〜20 が普通**なので、0 でも赤（弱い）にはせず「これから」と出します。赤くしても動けないためです。

### 採点から外したもの（2026-09-19）

| 指標 | 外した理由 |
|---|---|
| ドメインの年数 | 待つしかない。ただし**競合比較の表には残す**（新しいドメインほど時間がかかる、の説明に要るため。点は付けない） |
| 実ユーザーの規模（CrUX に載るか） | アクセスが増えた結果。直接の打ち手が無い |
| 対策キーワードの順位 | 施策の結果。KPI と順位計測にすでに出ている（二重に見せない） |
| ブランド名検索での順位 | 同上。ほとんどのサイトで自動的に 1 位になる |
| サイトの規模・信頼の手がかり | 打ち手はあるが、サイト内の話なので「構成」「信頼」のカードと重複していた |

### 競合との比較

競合サイトはクロールしないので、**外に公開されている指標だけ**（Ahrefs DR / Open PageRank と登録年数）を並べます。年数は採点に使いません。

| 指標 | 出どころ | 意味 | 注意 |
|---|---|---|---|
| LCP / INP / CLS / FCP / TTFB（75 パーセンタイル） | **CrUX**（Chrome の実ユーザーデータ） | 実際の利用者の体感 | **サイトの所有権も連携も不要**。ただしアクセスが一定数ないとデータが載らない |

1 ルール = 1 オブジェクトで、**条件・重要度・確度・確認できた事実・原因の候補・確認が必要なこと・打ち手・書いてはいけない結論**を持ちます。ルールを足してもエンジンのコードは増えません。

### 重要度と確度

| 重要度 | 意味 | スコア |
|---|---|---|
| critical | 計測不能・サイト障害・重大なインデックス問題 | 4 |
| high | 問い合わせや主要ページへ直接影響する | 3 |
| medium | 改善効果は見込めるが緊急性は低い | 2 |
| low | データ量が少ない・影響範囲が限定的 | 1 |

| 確度 | 意味 | 係数 |
|---|---|---|
| high | データから直接確認できる | 1.0 |
| medium | 複数の数値が同じ可能性を示す | 0.7 |
| low | 追加データがないと判断できない | 0.4 |

### 優先度スコア（並び順を決める式）

```
優先度スコア = 重要度 × 影響の大きさ(0〜1) × 確度 ÷ 実装負担
実装負担: small = 1 / medium = 2 / large = 3
```

報告書はこのスコアの**上位 3 件**を「まず手を付けるところ」として先頭に出します。

### 一次判定の閾値（`thresholds.ts`）

絶対的な良否基準ではなく、**ルールを発火させるかどうかの初期値**です。サイトの目的（問い合わせ / EC / 採用 / 来店 / メディア）ごとにプリセットで上書きされます。

| 閾値 | 既定値 | 使うルール |
|---|---|---|
| 最低分析日数 | 28 日 | D01 |
| 最低表示回数（サイト全体） | 500 | D03 |
| 最低表示回数（個別ルール） | 100 | Q03 など |
| 最低セッション数 | 100 | D03 |
| 「増加」とみなす増減率 | +20% 以上 | T01〜T09 |
| 「減少」とみなす増減率 | -20% 以下 | 同上 |
| 「横ばい」とみなす範囲 | ±5% 以内 | 同上 |
| 掲載順位の有意な変化 | 2.0 | T08・T09・X17 |
| 指名検索依存とみなす比率 | 60% 以上 | Q01 |
| クエリ取得率が低い | 70% 未満 | D04 |
| 低 CTR（1〜3 位） | 3% 未満 | Q04 |
| 低 CTR（4〜10 位） | 1% 未満 | Q05 |
| デバイス間の CTR 差 | 40% 超 | V01・X15 |
| 低エンゲージメント率 | 40% 未満 | L04・X14 |
| 低フォーム完了率 | 30% 未満 | K05 |
| 日別の異常値 | 中央値の 3 倍 | D08・T10・T11 |
| トップページ集中 | クリックの 60% 以上 | P01 |
| 対象外の国の表示 | 20% 以上 | D14・G02・G03 |

**増減の向きは 3 段ではなく 4 段です。**±5% 以内が「横ばい」、±20% を超えたら「増加 / 減少」、その間は **"unknown"（どちらとも言えない）** として断定しません。

### 訪問後の流れ（ファネル）の目安

段階ごとに普通の水準が違うため、**素の率どうしを比べません**。目安に対してどれだけ足りないかで「いちばん落ちている段階」を決めます。

| 段階 | 既定の目安 | BtoB（問い合わせ） | EC |
|---|---|---|---|
| 読まれた（エンゲージメント率） | 55% | 55% | 60% |
| 問い合わせ導線を押した（訪問のうち） | 3% | 2% | 5% |
| フォームを開いた（押した人のうち） | 50% | 50% | 60% |
| 送信した（開いた人のうち） | 40% | 40% | 50% |

### 主な計算式（`metrics.ts`。§0 の約束 3・4 に従う）

```
増減率           = (当期 - 前期) ÷ 前期          前期が 0 なら「新規発生」
CTR              = クリック ÷ 表示回数            行別 CTR の平均は使わない
エンゲージメント率 = エンゲージのあったセッション ÷ 全セッション
CTA クリック率    = CTA が起きたセッション ÷ 全セッション
フォーム開始率    = フォーム開始セッション ÷ CTA セッション
フォーム完了率    = フォーム完了セッション ÷ フォーム開始セッション
Organic CVR      = 自然検索のフォーム完了セッション ÷ 自然検索セッション
クエリ取得率      = クエリ一覧のクリック合計 ÷ サイト全体のクリック
指名検索比率      = 指名クエリのクリック ÷ クエリ一覧のクリック合計
```

**クエリ取得率と指名検索比率は必ず「一覧に出たクエリの中での比率」**として扱います。Search Console は少数のクエリを匿名化して一覧から外すため、サイト全体の比率ではありません。

### 再現性

`RULES_VERSION` / `THRESHOLDS_VERSION` を実行記録に保存します。**同じデータと同じ版なら、同じ項目が必ず発火します。**

## 8. MEO（Google ビジネス プロフィール）の採点

**コード**: `src/lib/maps/score.ts`（採点）/ `criteria.ts`（基準の開示）/ `owner-input.ts`（オーナー申告）
**採点基準の版**: `SCORE_RULES_VERSION = 2`（2026-09-13 に厳しく改定）

### 計算方法

4 カテゴリ（基本情報 / 投稿 / 写真 / レビュー）の重み合計が 100。`pass` = 満点、`warn` = 半分、`fail` = 0。
**Places API では取れない 9 項目**（説明文・開業日・メニュー・投稿・写真の日付・ロゴ / カバー・返信など）は、オーナー申告があればそれで採点し、無ければ `unavailable` として一覧には出すが分母から外します（約束 1）。

### 主な閾値（v2）

| 項目 | 基準 |
|---|---|
| 平均評価 | 4.5 以上で良好、4.2 以上で許容 |
| 口コミ件数 | 100 件以上で良好、50 件以上で許容 |
| 口コミの新しさ | 30 日以内が良好、90 日超で古い |
| オーナー写真 | 5 枚以上 |
| 写真の総数 | 10 枚以上 |
| 写真の解像度 | 1,024px 以上（低解像度が半数を超えると要改善） |
| 写真の新しさ（オーナー申告） | 31 日以内が良好、90 日超で古い |
| 口コミ本文の割合 | 20 文字以上の本文が 6 割以上 |
| 属性（設備・サービス） | 5 件以上。**「はい」だけ数える** |
| 説明文（オーナー申告） | 200 文字以上、禁止表現なし |
| 投稿（オーナー申告） | 直近 4 件以上 |
| 口コミへの返信率（オーナー申告） | 9 割以上で良好、5 割以上で許容 |

**採点基準 v2 でスコアは全体に下がります。**履歴が v1 と直接つながらない旨を報告書の末尾に明記しています。

## 9. AI の使い方と、生成内容の検証

**コード**: `src/lib/seo-analysis/ai/`（`analyze.ts` = 分析、`schema.ts` = 出力の型、`verify.ts` = 検証、`second-opinion.ts`）

### 分担

```
計算はプログラム → 診断はルール → 説明は LLM → 承認は人間
```

### AI に渡すもの・渡さないもの

- **渡すのは事実シート（`Fact` の配列）だけ。**HTML も URL の中身も渡しません。
- 事実には ID（`S-03` / `N-01` など）が振ってあり、AI は**主張ごとにこの ID を引用**します。
- 個人情報は渡しません。いま渡しているのは集計値と URL だけです（CRM を入れる段階で匿名化の層が必須になります）。

### 検証（`verify.ts`）

1. 生成された本文の**数値を事実シートと照合**し、シートに無い数値があれば 1 回だけ作り直させる。
2. それでも残れば「未検証の数値」として画面に注意を出す。
3. 事実シートに無い ID を引用した主張は**表示しない**（`dropUnknownIds`）。

### 回数と費用

| 項目 | 値 |
|---|---|
| 精密診断の月間回数 | 10 回（`SEO_ANALYSIS_MONTHLY_LIMIT`。運営者は無制限） |
| 1 回の収集につき AI 分析をやり直せる回数 | 3 回 |
| 実費 | AI の生成（数十〜数百円）+ SerpApi（1 回数円 × 7 検索）。クロール・PSI・CrUX・RDAP・Open PageRank は 0 円 |

## 10. 数字を出すときにしてはいけない解釈（横断）

[diagnosis-rules-spec.md](./diagnosis-rules-spec.md) §18 の全文がシステム全体の禁止事項です。特に間違えやすいものを再掲します。

- クエリ一覧の合計を**サイト全体の合計とみなさない**
- 平均掲載順位を**個々のキーワードの順位として扱わない**（表示回数で重み付けした平均です）
- 表示回数が少ないときの CTR を重大な問題として扱わない
- モバイル CTR が低いだけで**レスポンシブ表示の問題と断定しない**（検索結果側の可能性がある → X15 / X16 で切り分ける）
- 海外表示が多いだけで**海外需要があると断定しない**
- 「検索での見え方」が空欄でも**構造化データのエラーと断定しない**
- URL が複数あるだけで**重複コンテンツと断定しない**
- 滞在時間が長いだけで良いページと断定しない／直帰率が高いだけで悪いページと断定しない
- **イベント数を問い合わせ人数として扱わない**／キーイベントを受注として扱わない
- Search Console のクリック数と GA4 のセッション数の**完全一致を求めない**（20〜30% の差は正常）
- 前年同期がない状態で**季節性を断定しない**
- サイト更新と数値変化の**時期の一致だけで因果関係を断定しない**
- アクセス増加と売上増加を同一視しない
