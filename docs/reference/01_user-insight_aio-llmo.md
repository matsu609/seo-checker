# User Insight「AIO/LLMO 対策」カタログ 分析

- ファイル: `WebUI2Catalog_AIO.pdf`（10 ページ、16:9、Keynote 作成、作成日 2026-06-22）
- 提供元: 株式会社ユーザーローカル
- 製品: User Insight（アクセス解析・ヒートマップ・Web 接客の統合ツール）。本資料はその中の AIO/LLMO 対策機能に絞ったカタログ
- 特徴: アクセス解析ツールが母体のため「生成 AI からの流入」を実データ（PV/CV）で持っている点が他社と異なる

## 1. 全体像（p2）: 4 ステップの運用サイクル

| ステップ | 提供機能 | 内容 |
|---|---|---|
| 整理 | 導入後案内 | どのプロンプト（質問文）をモニタリングするか、設定をサポート |
| 調査 | LLMO ダッシュボード / AI からの流入・引用チェック | 自社・他社を含めた引用状況を把握 |
| 対策 | 最適化レポート / 記事生成 | 優先対応事項のレコメンド、コンテンツ拡充 |
| 検証 | LLMO ダッシュボード / AI からの流入・引用チェック | 調査と同じ画面で効果を確認 |

「モニタリング対象の定義 → 計測 → 改善 → 再計測」というループ設計。seo-checker1 でも「登録（プロンプト / キーワード / 競合）→ 定期計測 → 改善提案 → 再計測」の骨格をそのまま流用できる。

## 2. LLMO ダッシュボード（p3）

- 登録するもの: プロンプト（質問文）、ブランド名、ドメイン（自社 + 競合）
- 対象 LLM: ChatGPT、Gemini、Claude、Grok、Perplexity の 5 種
- 目的: 各 LLM での引用状況とカバー率を一覧で定量的にチェック

### 画面構成（キャプチャから読み取り）

1. KPI カード（上部）
   - 平均ブランド言及率（例: 18%）
   - 平均ドメイン引用率（例: 14%）
2. アクションボタン: 「llms.txt作成ツール」「生成AIからの流入分析」「編集」（登録内容の編集）。ブックマーク（お気に入り画面登録）アイコン
3. 時系列推移（折れ線グラフ、日次、約 20 日分表示、凡例つき）
   - 指標切替: 平均ブランド言及率 / 平均ドメイン引用率
   - 系列切替: 会社別 / モデル別
   - 系列: 自社 + 競合各社 + 「未分類」（登録していないドメイン・ブランドの引用をまとめたもの）
4. 自社ブランド言及率（AI 別）: 横棒。例 ChatGPT 0% / Gemini 40% / Claude 20% / Grok 20% / Perplexity 10%
5. ブランド言及率ランキング: 会社別横棒。自社行に「自社」バッジ
6. ドメイン引用率ランキング: 会社別横棒。「未分類」が最上位（24%）に来る例が掲載されている = 登録外ドメインの引用が多いことを可視化している

### 詳細画面（引用内容の確認）

- LLM ごと（Claude / Grok など）のカードに「回答」本文をそのまま表示。回答中に自社サイトが紹介された箇所（例: 「4. VTuber ランキング（ユーザーローカル）URL: https://virtual-youtuber.userlocal.jp/schedules」）や、引用番号 [1][2][3] 付きの文がそのまま読める
- 「競合比較」表: 行 = 会社（「自社」「競合」バッジ）、列 = LLM × {ブランド, ドメイン}。言及・引用があれば ○
- 「ブランド名・ドメインを確認」リンクで登録内容へ

### 指標の定義（推定）

- ブランド言及率 = 言及されたプロンプト数 ÷ 対象プロンプト数（会社 × モデル × 日 で集計。「平均」は全モデル平均）
- ドメイン引用率 = 参照元に当該ドメインが含まれたプロンプト数 ÷ 対象プロンプト数
- グラフの 4/14〜4/23 は登録各社がすべて 0% になり、「未分類」だけが約 17% で続いている。登録内容（ブランド名・ドメイン）の変更やドメイン判定の失敗で、引用が一時的に未分類へ流れたと推定される。実装時は登録内容の変更履歴を持ち、過去分を再集計できるようにしておくとよい。また取得失敗は 0% ではなく「未取得」として扱う

## 3. 生成 AI からの流入（p4）

アクセス解析側の機能。「どの生成 AI からどれぐらい流入があるか、どのページが確認されているか」を確認できる。

- 流入元別アクセス数の割合（ドーナツグラフ、内側は 検索 / 参照元なし の大分類）: Google / Yahoo / 検索 / Facebook / Instagram / X(旧Twitter) / ブログ / SNS / メール / ニュース / **生成AI** / その他 / 参照元なし。生成 AI を独立チャネルにしている
- 参照元 URL 別ページビュー数ランキング（フィルタ「生成AI」を選択）
  - 例: chatgpt.com 163 PV / gemini.google.com 16 / www.perplexity.ai 12 / claude.ai 4 / copilot.microsoft.com 1
  - 列: No. / サイト種別（「その他（生成AI）」）/ URL（外部リンク、外部サイト分析へ）/ 期間中の累計 PV / CV / 直帰率 / 当月の PV / 平均滞在時間
  - フィルタ: サイト種別プルダウン、ドメイン（FQDN）検索
  - 「この表をダウンロード」「PDF」「ブックマーク」
- さらに「どのページが見られているか」までドリルダウン可能
- 期間選択（例 2025/06/01〜06/30）、デバイス切替（すべてのデバイス）
- 左メニュー（全体）: ダッシュボード / リアルタイム / コンテンツ / 流入・検索語 / ユーザー / 広告 / コンバージョン / SEO・LLMO / AI 記事生成 / ポップアップ / エクスポート / 設定

## 4. AI Overviews 引用チェック（p5）

「SEO/LLMO」メニュー配下のキーワード管理機能。登録キーワードが AI Overviews（Google 検索結果の AI による概要）で引用されているかを確認できる。

- キーワードをグループ（例: 「名称未設定(14)」）で管理。「+キーワードを追加」
- キーワード一覧の列
  - キーワード / 推移（スパークライン + 順位変化 ↘2, →0 など、赤 = 下落）
  - 自サイトの順位（最新 / 平均）
  - 競合サイトの順位（最新 / 平均）
  - **AI による概要**: 自サイト（○ = 引用あり、— = なし、「未取得」）/ 競合（同）
  - 登録日
- 表のダウンロード、タブ「キーワード一覧 / 広告」
- 上部: 日次の積み上げ棒グラフ（期間 2025/11/01〜11/20、25% の目盛）。上位表示シェアの推移と推定
- 「今日の検索結果」画面: AI Overviews の本文全文と「引用サイト」一覧（タイトル + URL + favicon）。自社の URL には「自社」バッジ
- サブメニュー: コンテンツ調査（SEO 対策 / LLM 引用チェック）、SEO アドバイス、主要ページパフォーマンス、検索キーワード別（検索上位サイトの推移、キーワードグループ）、ドメイン別（競合サイト・自社サイト）

## 5. AIO/LLM 最適化レポート（p6 左）

URL を入力して単一ページを診断する機能。「AI フレンドリーかの調査、優先対応事項のレコメンド」。

- 上部タブ: メタタグ・見出し（この中に AIO/LLM 最適化レポート）/ 検索流入キーワード / 広告出稿キーワード / 表示速度・コアウェブバイタル（モバイル）/ アクセシビリティ（モバイル）

### レポートの構成

- 「AIO / LLM 最適化スコア」0〜100（例: 86、「良好」バッジ、プログレスバー）
- 総評テキスト（LLM 生成と推定）。例: 「ページ本文は十分に抽出できており、内容理解には大きな支障はありません。また、検索エンジンや AI によるクロールも基本的には可能な状態です。一方で、見出しや h1 タグ、構造化データが未設定なため、主題や重要情報が AI に伝わりにくい傾向があります。さらに、画像の alt 属性不足も補足情報の伝達性に影響していますので、改善が望まれます。」
- 「ページ情報を再取得」ボタン
- セクション（ページ内リンク）: 本文抽出・評価 / 内部リンク構造 / robots / llms / 構造化データ / Head 情報 / セマンティックタグ / 見出し構造 / 画像 alt 属性
- 各セクションは表形式: 評価項目 / ステータス（適切・良好などのバッジ）/ 内容（測定値・評価・理由）/ 備考（詳細・改善提案）
  - 例（抽出結果）: 文字数ボリューム「10003 文字」= 適切（AI に十分なコンテキストを提供できるかの目安）、ノイズ除去率「9%」= 良好（ヘッダーやフッターなど不要要素の除去率）、本文の要約評価（「本文は VTuber 関連のランキングやグループ分け…情報自体は整理されています。しかし、冒頭からグループ名など…」）

## 6. 記事生成（AI エージェント版）（p6 右）

- 左ペイン: チャット欄「指示を入力することで AI が自動で記事をリライトします」、クイック指示ボタン（文章を校正して / だ・である調に変えて / 関連語を増やして）、「残り 100 回/日」
- 右ペイン: 記事本文（見出し階層、箇条書き）。文字数表示（例 12,076 文字）
- 上部バー: 一覧に戻る / 構成案から作り直す / 前後移動 / 変更を保存 / クリップボードにコピー / ダウンロード
- メニュー: ファクトチェック / コピペチェック / 薬機法チェック / アイキャッチ画像生成 / 差分を確認
- テキストを範囲選択して、その範囲だけにリライト指示を出せる（トースト「選択範囲の文章に対してリライトすることができます」）

## 7. llms.txt 生成ツール（p6 下）

6 ステップのウィザード: ① 基本情報 → ② クロール設定 → ③ 会社情報 → ④ コンテンツページ → ⑤ 執筆者・RSS → ⑥ 結果

- 基本情報: クロールの許可（許可する / 許可しない）、トップページ URL（自動入力）、言語設定（日本語・英語などタグ形式で複数選択）、「次へ」

## 9. seo-checker1 に取り入れたい設計ポイント

1. **「未分類」バケット**: 登録外ドメインの引用をまとめて可視化する。競合の見落としに気付ける
2. **会社別 / モデル別の 2 軸切替**: 同じ日次データを 2 通りに集計するだけで実装でき、価値が高い
3. **回答原文の保存**: 率だけでなく「どの文脈で言及されたか」を後から読めるようにする
4. **「未取得」状態の明示**: ○ / — / 未取得 の 3 値。取得失敗を 0 と混同しない
5. **単一ページ診断のスコア + 表形式の根拠**: 評価項目 / ステータス / 測定値・理由 / 改善提案 の 4 列は全診断機能で共通フォーマットにできる
6. **AI 流入チャネル**: GA4 連携で「生成 AI」チャネルを作る（参照元ドメインの辞書で判定）
7. **チャット + 範囲選択リライト**: エディターの UX として実装コストの割に体験が良い
